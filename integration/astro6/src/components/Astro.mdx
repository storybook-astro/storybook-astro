# Astro Components

Pure Astro components rendered **server-side** via Astro's [Container API](https://docs.astro.build/en/reference/container-reference/). No framework runtime is loaded — interactivity is handled with inline `<script is:inline>` tags and vanilla JavaScript.

## How It Works

1. The renderer detects Astro components by the `isAstroComponentFactory` flag (set by `vitePluginAstroComponentMarker`)
2. A render request is sent to the Vite dev server middleware via HMR
3. The middleware renders the component using `AstroContainer.renderToString()` with the provided props and slots
4. The rendered HTML is injected into Storybook's canvas
5. Inline scripts are re-executed to add interactivity

## Props & Slots

Props are passed via `args` in the story and received through `Astro.props` in the component. Slots are passed as HTML strings in `args.slots`:

```jsx
export const Example = {
  args: {
    title: 'Hello',
    slots: {
      default: '<p>Slot content</p>',
      named: '<span>Named slot</span>',
    },
  },
};
```

## Static Builds

In `storybook build`, Astro components are **pre-rendered at build time** — changing args via the Controls panel has no effect. Framework components (React, Vue, etc.) remain fully interactive.

## Documentation

Each component's description and props table is generated from the JSDoc in its
`.astro` frontmatter — pick a component in the sidebar and open its Docs tab.
Story files declare no `argTypes`, so the table always matches the component:

```astro
---
/** A simple content card with optional highlight styling. */
interface Props {
  /** Card heading text. */
  title?: string;
  /** Applies a highlighted visual style. */
  highlight?: boolean;
}

const { title = 'Default title', highlight = false } = Astro.props;
---
```

Slots are the exception: they have no TypeScript representation, so describe
them in the component's own JSDoc block.
